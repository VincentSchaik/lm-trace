RAG (retrieval-augmented generation) gives a language model knowledge that it did not learn in training. First, the documents are cut into chunks and the embedding model turns each chunk into a vector: this is the index. Then the question also becomes a vector, the search finds the chunks with the nearest vectors, and the page puts these chunks in the prompt. The chat model writes the answer from that text. The example documents are invented, so the model cannot know them.

Index → Question → →
1Chunks documents → chunks

The documents are cut into chunks: small pieces of text that the search can find one by one.

  • Small chunks are precise, but a sentence such as "It is closed on Sunday" can lose what "it" means.
  • Large chunks keep the context, but one vector must then carry many topics.
  • With Fixed size, the overlap (shaded) repeats the end of a chunk at the start of the next one. A fact cut at a border is then complete in one chunk.
More

Most real tools set a maximum size in tokens and an overlap, and try to cut at a paragraph or sentence border first. Some tools also cut by document headings, by changes in meaning (with an embedding model), or with an LLM that selects the cut points. These give better borders, but the idea is the same: each chunk must hold one complete fact.

2Embeddings chunk → one vector

A separate, small embedding model (not the chat model) reads each chunk and gives one vector: a list of numbers for the meaning of the text.

  • Texts with a similar meaning get vectors that point in a similar direction.
  • The vectors of all chunks are the index. The page makes the index one time and keeps it until the documents, the split or the model change.
  • Blue = a positive number, grey = a negative number.
More

On the Tokenizer page, each token gets one row of the chat model's table. Here, all layers of the embedding model make one vector for each text. Some embedding models expect a task prefix in front of the text, for example task: search result | query: .

3Search question vector → nearest chunks

The question becomes a vector with the same model. The search keeps the k chunks with the highest cosine similarity.

  • Cosine similarity measures how much two vectors point in the same direction: 1 = the same direction, 0 = not related.
  • A chunk can match without a shared word, because the vectors compare meaning, not spelling.
  • The search always returns k chunks, also when no chunk has the answer: it finds the nearest text, not the truth.

4Prompt chunks → context in the prompt

RAG changes only the prompt: the page puts the top k chunks, with their numbers, into the user message.

  • The instruction tells the model to use only these chunks and to give their numbers.
  • The chat model does not see the vectors, the scores or the other chunks. It sees only this text.

5Answer prompt → answer

Compare the two answers.

  • Without RAG, the model can use only what it learned in training. For an invented document, it must guess or say that it does not know.
  • With RAG, it can use the chunks. Click a chunk number in the answer to see the chunk.
  • If the correct chunk is not in the top k, the answer is wrong too: the search limits the answer.
