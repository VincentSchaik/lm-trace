Tools

A playground for tool calling: how tools let a model interact with the world. Try the ready tools with the examples, or create your own, and see each step of the real run.
How it works

The model does not call a tool. It only writes a tool call: the intention to use a tool. Two programs do the rest. LM Studio, the inference server, runs the model and parses its output into JSON. The harness (this page and its server) executes the tool and sends the result back.

  1. Tool creation · Tools tab. You create a tool: a function with a name, a description and parameters, and the URL or the Python code that runs it. The harness turns it into the tool definition, a JSON schema. Only the tools that are on go to the model.
  2. Tool definition · Tool list. The harness defines each tool that is on. LM Studio: a JSON schema in the format of the OpenAI Function Calling API. Custom note: text in the system prompt. Sending request sends the definitions in each model call, and Applying chat template puts them into the prompt.
  3. Tool selection · Generating tokens. The model thinks, and selects a tool or no tool.
  4. Tool calling · Generating tokens: the model writes the call. Parsing output, Serializing JSON: LM Studio parses it. Parsing tool_calls, Validating tool call: the harness parses and validates it. Executing tool: the server executes it. With Permissions set to Ask every time, the harness asks you first: Allow or Deny.
  5. Output processing · Appending observation: the result goes back to the model as an observation. In the next model call, the model writes the answer.

Some models learned special tool tokens in training (native tool use). LM Studio puts the tools into the chat template of these models. Other models get the tools as a text note with the [TOOL_REQUEST] format (default tool use), and must follow it.
